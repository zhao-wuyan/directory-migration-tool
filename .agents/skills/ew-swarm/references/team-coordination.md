# Evolve Swarm Coordination

Use the exact canonical `session_id` (`<session>`) and `run_id` (`<run>`) returned by Evolve. The Evolve database holds the roster and result receipts; Python owns ACO assignments, history, pheromone updates, and convergence under `team_dir` (`{run_dir}/work/team/`, passed via `--session` to `aco.py`).

1. **Materialize & initialize**: Call `evolve run task controller --session <session> --run <run>` to materialize the committed Python scripts into `{run_dir}/work/controller/` and capture the returned `script` path (`{run_dir}/work/controller/aco.py`) and `config_template`. Prepare `swarm-config.json` in `work/team`, then invoke `python <controller.script> --session {run_dir}/work/team --run-dir <run_dir>` for `init`, `select --iter <k>`, `update --iter <k>`, `converged`, and `report`.
2. **Assign & dispatch**: Register each ant assignment (`ANT-<k>-<i>`) with:
   `evolve run task assign --session <session> --run <run> --id ANT-<k>-<i> --role <worker-id> --path outputs/ant-<k>-<i>.json --actor <coordinator> --expected-orchestration-revision <revision>`
   Start every dispatched worker with a **fresh context window** (reserve `fork` only for warm deep-dive branches needing primary-source reasoning; `scorer` must always start fresh and blind). Communicate via **sparse context pointers** — pass only `assignment_id` (`ANT-<k>-<i>`), `worker_id` (matching `--role`), canonical `session_id`, `run_id`, `run_dir`, `team_dir`, latest `expected_orchestration_revision` (from the final `assign` receipt), role document path, workspace boundary (shared workspace for read-only or JSON-output ants/scorers/analysts; isolated worktree or branch per worker for concurrent repo editors — see [host-adapters.md](host-adapters.md)), CLI Run instructions, and the shared `--reads` receipt path — then join/await all dispatched workers.
3. **Worker reporting & failure**: Each worker reads its role from the bound revision (`evolve run read skill <run> roles/<role>/role.md --from SKILL.md --session <session>` when available), writes and self-validates its JSON artifact, then runs:
   `evolve run task report --session <session> --run <run> --id <assignment-id> --actor <worker-id> --summary "<result>" --expected-orchestration-revision <revision>`
   (`--actor` MUST equal `--role` registered in `assign`.) On `REVISION_CONFLICT`, query `evolve session get --session <session>` for the current `orchestration_revision` and retry with a new `--request-id` (or omit `--request-id` so the CLI derives a distinct fingerprint). Retrying an uncertain response reuses the original `--request-id` and payload. Follow the active host's worker completion and workspace-landing rules in [host-adapters.md](host-adapters.md) so any isolated branch/worktree changes land before worker teardown. If a worker fails or reaches `partial_completion` without a valid JSON deliverable, keep `outputs/` free of invalid JSON and skip `evolve run task report`; instead return structured failure / `partial_completion` details to the coordinator so the coordinator cancels the assignment via `evolve run task cancel --session <session> --run <run> --id <assignment-id> --actor <coordinator> --expected-orchestration-revision <revision> --reason "<reason>"`.
4. **Verify & score**: Check `evolve run task list --session <session> --run <run>` against the controller batch (every assignment has `result` or `cancellation`). For LLM scoring, register `SCORE-<k>` against `work/team/scores/iter-<k>-scores.json` via `evolve run task assign`, dispatch with `worker_id` and current `expected_orchestration_revision`, wait/join for it, then run `<controller.script> update`. If accepting ACO score fallback, cancel the failed scorer via `evolve run task cancel` (with assignment ID, current revision, and reason) before passing `--allow-score-fallback`.
5. **Resume**: Use `evolve run check` and `evolve run get` together with saved `team-session.json`, controller assignments, and roster. Reuse completed jobs, retry unfinished assignments under original IDs, and re-run `<controller.script> select --iter <k>` for the persisted batch.
6. **Seal & harvest**: Run `<controller.script> converged` and `<controller.script> report`, synthesize declared artifacts, write `report.md` and finalize `team-session.json`, then seal (when self-started) via the Evolve controller guide (`evolve skill workflows show session-run` / `skills/ew-orchestrate/references/orchestrator-run-loop.md`) and harvest reusable findings via `ew-knowledge` (`evolve skill workflows show ew-knowledge` / `skills/ew-knowledge/SKILL.md`).
