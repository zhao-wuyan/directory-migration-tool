### B0：建立两个各 500 MiB 的受控测试卷

新增 `test/vhd/Manage-TestDisks.ps1`、`test/vhd/TestDiskGuard.ps1`、`test/vhd/Run-Tests.ps1` 和 `test/MigrationSafetyHarness/MigrationSafetyHarness.csproj`、`Program.cs`。仓库未见等价测试环境，采用现有 .NET 8 控制台工具链；runner 引用 MigrationCore，目标 `net8.0-windows10.0.19041.0`，不另建复制引擎。

**固定接口**：`Manage-TestDisks.ps1 -Action Check|Create|Mount|Dismount -RunId <GUID>`，默认 Check；Create 需要显式运行，其他动作只处理已登记 Run。`Run-Tests.ps1 -RunId <GUID> -Suite Boundary|Identity|Probe|Copy|Switch|Backup|All [-LaunchUi]`。未知参数拒绝；不提供任意磁盘号、任意镜像路径、重新格式化或一键全盘清理参数。

1. 只读预检管理员权限、已安装 SDK >=8，以及 `New-VHD/Get-VHD/Mount-VHD/Dismount-VHD` 和 Storage 模块命令是否可用。选用微软 Hyper-V PowerShell 的动态 VHDX 创建接口，不创建虚拟机。命令可用性 `unverified — confirm first`；缺命令/权限停止，报告前提，不安装或启用 Hyper-V/Sandbox、不改 BIOS 或重启，不退回临时目录测试。镜像所在盘需至少 2 GiB 可用供两个镜像增长，构建空间另行检查；运行中宿主可用空间低于 1 GiB 时停止写入测试。
2. 每次 Create 在 `%LOCALAPPDATA%\MoveWithSymlinkWPF-TestLab\runs\<GUID>` 创建专用 WorkRoot；拒绝祖先重解析点，不复用已有目录。仅新建 `source.vhdx`、`target.vhdx`，各用 `New-VHD -Path <精确新路径> -Dynamic -SizeBytes 524288000`，不得使用 SourceDisk/ParentPath，不读取真实磁盘作为镜像内容。镜像已存在就停止，不覆盖。
3. 挂载用 `Mount-VHD -Path <精确路径> -NoDriveLetter -Passthru`。每一步重新以 Get-VHD 的精确镜像路径取得关联 DiskNumber，再用 Get-Disk 核对身份、容量、非 IsBoot/IsSystem 和初始 RAW。仅本次 Create 成功且仍 RAW 的磁盘才能 `Initialize-Disk -PartitionStyle GPT`，随后新建单一数据分区并格式化 NTFS；不要复制官方示例的无检查连管道，不运行 Clear-Disk，不对“所有 RAW 磁盘”操作。
4. 分配系统空闲盘符，不硬编码盘符或磁盘号。保存 WorkRoot 内 `lab.json`：`schemaVersion=1,runId,imagePaths,diskUniqueIds,partitionGuids,volumeUniqueIds,volumeSerials,driveLetters,createdAtUtc`；卷标只作显示，不作授权。Mount 仅重新挂载登记镜像、匹配身份并更新当前盘符，绝不重新初始化/格式化。登记失败停止，保留镜像，只卸载能证明归属本次的挂载。
5. 源盘建立 `Data\Sources\Sample`、`Data\Protected` 和 `LabState`；目标盘建立 `Data\Targets`。业务源、目标、staging、备份、测试链接和事务记录只在两卷内；WorkRoot 仅放镜像、发布包和测试日志。跨卷链接仅允许指向这两个白名单卷。每个用例前及危险动作前通过当前句柄最终路径/卷序列号与登记身份验证，含路径组件边界和祖先重解析点检查；盘符被替换、卷离线、路径越界、UNC/设备路径或未知链接一律拒绝，不跟随到真实宿主路径。被测迁移应使用 `Data` 子目录，不直接迁移卷根。
6. 先构建边界 guard 和 Boundary suite，再运行存在已知缺陷的业务代码。runner 默认不运行，必须通过 `Run-Tests.ps1` 提供登记路径；guard 不是操作系统安全边界，管理员程序仍有宿主权限，此风险不能被文档描述消除。系统目录拒绝用解析器夹具，越界链接用两个测试卷内的 Protected 假数据，不向真实 Windows/用户/Nova/Docker 目录创建链接、改名或删除。不得为测试改宿主全局 ACL、服务、网络、回收站策略或用户配置。
7. 打包复用当前项目，源复制到 WorkRoot\BuildSource（排除 bin/obj/.git，拒绝重解析点）；保留项目结构、version.json 与 Handle 资源。不调用 publish.ps1/run.ps1/test-publish.ps1，避免版本/项目回写和启动生产应用。生成专用 quick-migrate.json 替代构建副本中的嵌入配置：`profiles=[]`，唯一 standaloneSource 指向本次源卷 `Data\Sources\Sample`，`defaults.targetStrategy="unified"`、`unifiedTargetRoot` 指向本次目标卷 `Data\Targets`、`robocopyThreads=2`、`restoreKeepTarget=true`（B4 删除该旧属性时同步移除）。外部配置同样生成，缺失/不符就不启动。使用已有包缓存离线还原到 WorkRoot 私有缓存，缺依赖停止，不自动安装。

9. 测试入口显式注入源卷 `LabState` 作为事务目录，不读写用户现有应用状态。WPF 首先不启动；B1 提供经过双卷验证的测试状态目录注入后，`-LaunchUi` 才允许启动 WorkRoot 的专用应用包。新增专用测试启动参数 `--test-lab <lab.json>`，在 App.OnStartup 载入任何 ViewModel 前验证登记身份、专用包位置、配置和状态目录；生产启动不带此参数保持默认状态目录，带参数但任何检查失败必须退出，不回退生产配置。该参数不是迁移/删除执行命令，不绕过任何核心策略。App.xaml 的 StartupUri 初始化之前完成检查；若需由代码创建窗口，则一并移除 StartupUri，避免两个 MainWindow。
10. 回收站测试只操作两测试卷上的明确夹具，不调用全局清空回收站。永久删除仅本次夹具；回收失败不得降级。卷内多副本/填满用例逐项串行，普通用例预算每卷不超过 128 MiB；单文件最大 32 MiB，小文件集 1000×4 KiB。磁盘满用例用目标卷自己的 filler 消耗到不足复制所需空间，不填宿主盘；随后仅删除登记的 filler。其他故障用例结束不递归清空整个盘，通过新 Run 的两镜像重置，旧镜像默认保留，避免误删证据。

### B2：保留重命名快检，失败不丢实体

修改 `SimpleFileLockDetector`、`HandleHelper`，复用现有重命名机制和 Handle 诊断，清洁切换为 `Task<DirectoryProbeResult> CheckMigrationAsync(MigrationTransactionRecord transaction, IProgress<string>? log, CancellationToken ct)` 和 `Task<DirectoryProbeResult> CheckRestoreAsync(MigrationTransactionRecord transaction, IProgress<string>? log, CancellationToken ct)`。结果包含 `CanProceed`、`RecoveryRequired`、`ActualDataPath`、`Error`、诊断结果，不能继续使用 bool/out string 丢失实际数据位置。

1. 先做只读路径/关系/权限准入，再持久化唯一 `<源名>_lock_test_<transactionId>` 及源身份；冲突直接停止，不覆盖。首次 Move 成功后持久化 ProbeRenamed；恢复原名成功后核对身份并恢复 Prepared。`finally` 只释放句柄，不递归删除该目录。
2. 第一次改名失败：原路径不动，返回拒绝；改回失败：实际数据路径指向改名后目录，进入 RecoveryRequired，停止整个迁移。诊断同时考虑实际数据路径和原名冲突路径，不把新出现的原名目录误认成源。
3. Handle 仅失败时调用。改为 `Task<HandleDiagnosticResult> GetProcessesLockingPathAsync(string path, CancellationToken ct)`，结果区分 Found/NotFound/Unavailable/TimedOut；超时固定 5 秒，输出读取与进程等待共享截止，超时只结束本次启动的诊断进程并等待退出；不可吞异常解释成“未占用”。
4. 全仓迁移 `CanProceedWithMigration/CanProceedWithRestore/GetProcessesLockingPath` 调用者到新结果；包括手动预检与两个核心服务。实际编辑导出符号前先用 LSP references；已知主要消费者为 `MainViewModel`、`MigrationService`、`ReversibleMigrationService`，其他命中由本批一并迁移，不保留兼容 wrapper。

### B3：复制可控退出，基础核对成为切换硬门槛

修改 `FileStatsService`、`CopyOperationExecutor`；新增 `CopyVerificationService.cs`。现有 FileStats 只有聚合值，不能复用为逐文件清单；保留其进度用途，新增独立 manifest DTO，不把大小估算当完整性证明。

1. manifest 包含相对路径、File/Directory 类型、文件长度、LastWriteTimeUtc、必要属性，以及要求保存的 ADS/ACL 摘要；空目录、零字节文件均包含。枚举或元数据读取失败要向上报告，不继续返回“完整清单”；仅排除当前事务明确拥有的控制文件，不按 `.bak/.tmp` 名称泛化排除。
2. `CaptureAsync(string root, VerificationMode mode, CancellationToken ct)` 返回 manifest；`VerifyAsync(FileManifest sourceBefore, string sourceRoot, string targetRoot, VerificationMode mode, CancellationToken ct)` 比较源前后可观察变化和目标独立清单，返回含 `IsMatch/Mode/Mismatches` 的结果。Basic 不通读文件内容；ContentHash 用流式 SHA-256。Basic 通过只证明指定基础项一致，不能发现所有等长修改，不能标记“内容完全一致”。
3. 继续使用现有 Robocopy 执行器，去掉 `/MIR`，使用 `/E` 保留必要复制属性，不清除额外目标内容。复制目的地是本事务新建的唯一空 staging `<TargetParent>\.<TargetLeaf>.copy_<transactionId>`，先记父路径/身份，创建后记自身身份。核对通过后以不覆盖 Move 提升为最终目标；最终目标若已存在且为用户选定的空目录，先记录 `reservedEmptyTargetIdentity`，提升时重验身份/无内容后仅用非递归 Delete 删除这个空目录（期间出现内容则 Delete 失败并停止），再做不覆盖 Move。非空、身份变化或新出现的未知目标一律停并保留 staging。调用方不再预建最终目标目录，只准备父目录/staging；禁止向非空未知目录复制或清空。源/目标/祖先身份变化、并发未知内容转冲突，不能认为移除 /MIR 就已完成所有保护。
4. `ExecuteAsync` 返回 `CopyExecutionResult`（退出码、实际 staging 路径、明确失败摘要），不再用总大小小于 98%仅警告作为成功门槛。Robocopy `>=8` 拒绝；较小退出码也不能绕过独立 manifest 核对。配置和 UI 仍显示最终目标，不把 staging 路径冒充用户目标。
5. 从 Process.Start 起进入统一 try/finally；取消注册覆盖启动后、Delay、stdout/stderr 和 WaitForExitAsync。取消时停止并等待本任务进程树退出，等待两条日志读取完成；确认未退出时报告 RecoveryRequired，队列不推进。只处理保存的本任务进程句柄/PID，不按进程名杀系统全部 robocopy。取消不删除 source、staging、备份或其他事务标记。
6. 内容核对通过后才记录 CopyVerified。源变化、缺文件、错路径、逐文件大小差异、未知额外内容或任何无法核对项都不得改名建链。

```powershell
.\test\vhd\Manage-TestDisks.ps1 -Action Check
$runId = [guid]::NewGuid().ToString()
.\test\vhd\Manage-TestDisks.ps1 -Action Create -RunId $runId
.\test\vhd\Run-Tests.ps1 -RunId $runId -Suite Boundary
```

- 用户明确选择双动态 VHDX，每盘 500 MiB，接受宿主执行的剩余风险；这取代原 Windows Sandbox 必须条件，但不授权接触真实业务数据。
- 不自动安装/启用宿主功能；New-VHD/Storage 模块权限和命令已在 B0 现场验证。今后环境变化导致缺项仍须停止报告，不暗中改用更危险的磁盘操作方案。
