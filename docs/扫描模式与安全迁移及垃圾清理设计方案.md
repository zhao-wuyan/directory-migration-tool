## 1. 设计结论

增加“磁盘扫描”和“垃圾清理”两个独立模式。扫描模式负责发现空间占用、筛选第三方软件目录、汇总迁移清单；迁移仍走现有手动迁移服务，不另写复制或链接引擎。AI 通过本地 MCP 读取用户授权的扫描视图，提交建议清单，不能启动迁移、清理、还原、修改规则或替用户确认。

安全原则是**默认拒绝、明确允许、执行前重验、保留原件、人工删除**，而非只维护一个系统目录黑名单。

重要前提：**第三方软件不等于低风险软件；扫描结果不是实时文件系统真相；成功建链不等于数据完整或软件兼容。** 无法可靠识别的目录可以显示占用，但不能直接迁移。

### 1.2 不纳入的能力

不做系统目录迁移、系统瘦身、注册表清理、重复文件删除、驱动迁移、自动结束进程、开机前迁移、自动删除备份、AI 自动操作、云端托管扫描服务。Treemap 可作为后续显示方式，不替代本次必需的目录树，也不是本次上线前提。

“不纳入”指这些操作不提供入口；不影响扫描时只读显示系统目录的占用。

### 2.2 与本次安全要求冲突的事实

1. **现有手动及一键迁移自动删除备份。** `MigrationService.cs:72-74`、`ReversibleMigrationService.cs:99-101` 均调用清理；`MigrationWorkflowHelper.cs:101-119` 通过 `Directory.Delete(backupPath, true)` 永久递归删除。不能原样接入。
2. **现有检查不是完整性证明。** `MigrationWorkflowHelper.cs:76-95` 只检查是否为重解析点以及目录是否可访问。复制器拒绝 Robocopy 退出码 `>= 8`，但总字节数低于源的 98% 只记警告（`CopyOperationExecutor.cs:477-489`）；未证明逐文件、ADS、ACL 或应用兼容性。
3. **现有保护路径覆盖有限。** `PathValidator.cs:8-15,61-68` 为固定 `C:` 路径和字符串前缀，既会误伤相似前缀，又无法覆盖其他系统卷、路径别名和高危第三方组件；同时整棵 `Program Files` 被阻止，与有条件允许第三方软件子目录的目标冲突。
4. **目标侧保护不足。** `PathValidator.cs:153-168` 仅拒绝相同路径及目标位于源内，未覆盖源位于目标内、物理别名、跨任务交叉覆盖。`HasUserContent` 在访问异常时返回 `false`（`:37-47`），不能据此认定目标为空。
5. **`/MIR` 具有删除目标额外内容的能力。** 不能因为入口曾检查“空目录”，就假设执行期间目标不会被替换或写入。新任务必须使用本任务独占、刚创建的空目标；无法证明独占则拒绝执行，而不是合并。
6. **旧备份发现方式不能作为删除授权。** 名称、时间戳、`.bak_*` 匹配只能提示发现，不能证明目录确为某次迁移的备份。
7. **还原也存在自动删除数据路径。** `ReversibleMigrationService.cs:399-400` 在相应配置下清除目标；`MainViewModel.cs:770-786` 手动还原只做一次提问后删除。若继续开放这些入口，需纳入统一保留/确认规则，避免从旧入口绕过新承诺。
8. **当前 UI 整体要求管理员权限。** `MoveWithSymlinkWPF/app.manifest:20` 为 `requireAdministrator`。MCP 不应因此要求用户的 Agent 也以管理员启动。

以上是静态核对结果，不是运行故障复现。第一阶段不执行数据操作。后续实现必须先修正这些共享安全接缝，再上线扫描迁移；不能只在新页面禁用按钮而保留核心服务的危险行为。

### 3.1 模块职责

| 模块（拟新增或扩展） | 职责 | 禁止承担 |
| --- | --- | --- |

依赖方向：UI → 核心应用服务 → 文件系统实现；MCP Bridge → 受限契约/IPC → 快照查询与建议收件箱。MCP 的契约项目不包含执行命令；扫描器只返回数据。

### 3.2 共享约束

- 扫描、手动选择、旧一键配置、AI 建议必须经过同一核心安全策略。系统/高危拒绝规则对所有新发起的迁移入口生效。
- 既有已迁移项仍可查看；恢复和修复采用专门的恢复校验，不因新的“应用允许列表”简单阻断用户恢复原状，也不得借恢复接口执行新迁移。
- 一个数据变更任务运行期间，清理、恢复、修复和另一迁移不得并行操作同一应用/目录。初始实现使用应用级单执行队列，优先保证可解释性。
- 本地事务记录落在受 ACL 保护的应用状态目录，以临时文件写入后原子替换，记录 `schemaVersion`；扫描元数据默认仅在内存，不默认落盘整盘清单。
- 不新增数据库依赖作为本次前提；规模验证若证明确有必要，再提出持久化方案变更，不提前建设索引平台。

## 4. 磁盘扫描模式

### 4.1 用户流程

1. 用户进入“磁盘扫描”，选择本地卷，查看文件系统、容量、权限与扫描能力。
2. 点击扫描；展示“读取 MFT → 构建目录关系 → 汇总占用 → 识别可迁移目录”的阶段。
3. 用目录树展开/收起、面包屑返回、按大小排序、搜索目录名，逐层定位空间。
4. 选中目录查看应用归属、占用口径、允许/拒绝原因、是否需关闭软件。
5. 仅允许符合策略的目录加入迁移清单；默认不勾选任何目录。
6. 可选择向已配对的 Agent 开放本次授权视图，等待建议；无需 AI 也能完整使用。

树至少展示：名称、逻辑大小、分配空间、占父目录比例、文件/目录数量、应用归属、可迁移状态。文件可查看占用，但本需求仅迁移目录，不提供单文件迁移或树内任意删除。

### 4.2 扫描后端选择

**建议主路径：本地 NTFS 卷的只读原始 MFT 扫描。** 在 `MigrationCore` 下用 C# 安全边界明确的解析器和 Win32 P/Invoke 实现；采用顺序分块读、紧凑记录和有界工作队列，不引入内核驱动。开源实现作为格式处理和测试用例参考，不直接启动外部扫描器充当正式后端。

| 后端 | 适用与优点 | 限制及显示 |
| --- | --- | --- |
| 原始 MFT 只读扫描 | 本地、已解锁 NTFS、有访问卷的权限；减少逐文件系统调用 | 必须完整处理记录、碎片、属性扩展；不是事务一致快照 |
| `FSCTL_ENUM_USN_DATA` | 可用于文件 ID/父关系索引或能力验证 | USN 记录不包含文件大小，不能单独满足磁盘占用统计；补全大小仍需要额外查询 |
| 目录遍历 | 非 NTFS、无原始卷能力或解析失败时可用 | 明示“普通扫描/部分结果”，访问拒绝和未知大小不当成 0；不承诺 MFT 速度 |

不把遍历后端冒充 MFT；不因普通扫描完成而宣布 MFT 需求完成。扫描降级只影响发现功能，不扩大迁移允许范围。初始迁移执行限定本地固定 NTFS 源/目标卷；其他文件系统可以浏览，但执行禁用并解释原因。

### 4.3 MFT 解析必须覆盖的事项

- 只以读取权限打开卷，通过 `FSCTL_GET_NTFS_VOLUME_DATA` 取得簇大小、记录大小、MFT 信息；不能假定记录永远为 1 KB。
- 从 MFT 自身记录的 `$DATA` run list 定位所有区段；支持碎片化 MFT 及 `$ATTRIBUTE_LIST` 扩展，不把连续范围误当整个 MFT。
- 校验记录签名、in-use 标记、update sequence/fixup、属性长度、边界、整数溢出；损坏记录标记缺失，不能越界或死循环。
- 文件身份使用卷身份加完整文件引用（包括序列号）；父记录引用也检查序列号，避免记录复用接错父目录。
- 处理 resident/non-resident `$DATA`、命名 ADS、稀疏和压缩分配空间、扩展记录；不能直接采用可能不完整的 `$FILE_NAME` 大小作为最终大小。
- 区分 DOS 短名与有效长名；一个文件可能有多个目录项/硬链接，不能简单丢掉除第一个之外的名字。
- 目录重解析点只显示自身及标志，不跟随目标扩展；孤立父节点归入“未解析位置”，禁止迁移。
- 不识别的 NTFS 特性、版本或记录标为 `Unsupported/Incomplete`，对涉及该子树的迁移关闭授权。
- 卷读取失败、BitLocker 未解锁、权限拒绝、取消和内存不足均有明确结果；不修改权限、卷或 USN 日志来强行完成扫描。

### 4.4 大小和空间收益的口径

| 字段 | 含义 |
| --- | --- |
| `LogicalBytes` | 文件内容长度；ADS 单列并在总逻辑数据量中明确计入 |
| `AllocatedBytes` | 数据流实际分配空间；不是简单按簇向上取整，稀疏/压缩必须区别处理 |
| `UniqueAllocatedBytes` | 按卷内文件身份去重后的数据分配量；硬链接共享空间不重复计入卷总量 |
| `MetadataBytes` / `UnknownBytes` | 可识别目录索引等元数据与无法归属部分；不声称目录求和必等于卷已用空间 |
| `RequiredTargetBytes` | 执行前根据真实文件、目标能力、可能解压/稀疏变化计算的保守复制需求，不直接用 MFT 已分配量 |
| `PotentialReclaimBytes` | 原始备份最终永久移除后可能释放的空间，不承诺精确值 |

目录树对硬链接的“唯一占用”采用确定的归属规则（稳定排序的代表目录项），其他目录项标注“共享/已计入其他位置”；集合合计用文件身份去重。选择目录含硬链接时，初始版本拒绝迁移，避免跨卷复制破坏共享语义。

**改名备份仍在源盘，不释放原盘空间。** 迁移完成页分别显示“目标新增占用”“源盘保留备份”“待用户删除后可释放”；移入回收站也通常不立即释放空间。不以迁移成功虚报清理收益。

### 4.5 快照与性能设计

- `ScanSnapshot` 含 `scanId`、卷 GUID/序列号、起止时间、后端、覆盖状态、错误数、策略版本；每个节点持有稳定 `nodeId`，不是路径授权令牌。
- 活跃卷扫描可能跨越文件增删改。USN 可用时记录前后水位并标注变化；日志缺失、截断或无法确定则标为需实时复核，不自动创建日志。
- 取消后部分结果可浏览，不能直接用于执行；已选候选必须独立完整重验。
- 内核使用紧凑数组、文件 ID 索引、名称池、父子邻接关系；按子节点向父节点汇总，避免逐文件反复构造完整路径和遍历所有祖先。
- UI 用按需展开、分页与行虚拟化；不得给百万文件各创建一个 ViewModel/ObservableCollection 项。完整路径仅在显示、选中或查询页时生成。
- 进度按实际阶段展示；未知总量不伪造精确百分比。扫描不在 UI 线程执行。
- 拟定验收目标：百万级目录项可完成扫描和展开；常规可见树展开/排序的 UI 响应目标 200 ms 内；取消反馈目标 1 s 内。扫描耗时、峰值内存必须在固定机器与数据集实测记录，不能引用开源项目宣传数字作为本项目结果。

## 5. 迁移安全策略

### 5.1 判定状态和优先级

返回 `Denied`、`Unrecognized`、`RequiresReview`、`Eligible`，并附 `reasonCodes`、规则版本和证据。只有 `Eligible` 可加入可执行清单；`RequiresReview` 可进入“待核对”区，但不能点击开始。AI 的自然语言判断不能改变这些状态。

判定顺序：路径/身份解析 → 系统与高危拒绝 → 子树特殊结构检查 → 第三方应用归属 → 受支持应用/目录规则 → 目标与容量 → 实时运行状态。**拒绝永远优先于允许。** 用户确认、管理员权限、编辑 JSON 或 AI 都不能解除硬拒绝。

### 5.2 系统及高危拒绝范围

路径通过 Windows API、Known Folders、卷/分区身份、系统配置和服务/驱动登记解析，不硬编码系统永远位于 `C:`；以下路径仅为常见实例。

| 类别 | 典型范围 | 策略 |
| --- | --- | --- |
| 操作系统及维护 | 当前和已识别其他 Windows 安装、`Windows.old`、WinSxS、System32、SysWOW64、Installer、SoftwareDistribution、系统更新/恢复目录 | 整棵禁止迁移；不以其中存在第三方文件为例外 |
| 启动/恢复/卷元数据 | EFI/系统保留/恢复分区、Boot、Recovery、System Volume Information、`$Recycle.Bin`、NTFS 元数据 | 禁止作为源和目标；不允许挂载点绕过 |
| 系统级容器 | 卷根、Program Files/Program Files (x86) 根、ProgramData 根、Users 根、整个用户配置文件、AppData 根 | 容器整体不可迁；仅非硬拒绝区内经规则批准的应用子目录可单独判定 |
| Windows 与包管理组件 | WindowsApps、Windows 服务/共享组件、Common Files、ProgramData/Microsoft、AppData 中 Microsoft/Windows 关键区、MSIX/UWP 包目录 | 默认整棵拒绝；不通过移动到另一个盘名绕过 |
| 身份、密钥与安装维护 | 系统账户配置、证书/凭据/密钥目录、安装包缓存、驱动存储、系统注册表配置 | 拒绝，不以“缓存”命名放行 |
| 高危第三方 | 驱动、杀毒/EDR、磁盘加密/备份过滤驱动、启动项基础组件、登录组件、关联系统服务的安装/数据目录 | 拒绝；第三方身份不是豁免依据 |
| 特殊文件系统结构 | 源或祖先/子树中的链接、junction、挂载点、云占位、硬链接、EFS，以及尚未验证复制语义的结构 | 初始策略拒绝迁移；扫描可只读展示 |
| 工具自身与未完成事务 | 当前程序、状态库、执行目录、待验证备份、清理隔离区、运行任务的源/目标 | 禁止再次迁移或作为清理候选 |
| 非第三方软件数据 | 任意个人文档、下载、桌面、未知大目录 | 可显示，不因“大”而自动允许迁移 |

单个系统文件不支持迁移；若其位于候选子树或有受保护身份，整个候选拒绝。Windows Resource Protection、TrustedInstaller 所有者、文件属性可提供拒绝证据，但不能仅靠某一个属性或签名判断安全。

### 5.3 如何认定第三方软件目录

`ApplicationCatalog` 综合 HKLM/HKCU 卸载项（兼顾 32/64 位视图）、安装位置、有效文件签名/发布者、已知应用规则和用户本地关联信息。注册表显示名称、DisplayIcon 和目录名都属于证据，不是可信授权源。

允许规则必须描述：`applicationId`、版本范围、身份匹配、安装根定位器、精确允许的相对目录、禁止子目录、运行进程/服务、所需文件系统能力、已验证链接兼容性和验证方法。

建议初始支持普通桌面软件的独立资源/模型/素材/可再定位数据目录，以及经过验证的普通安装目录。整个软件根仅当规则明确支持时允许；不能默认将安装根以下任意子目录都设为安全。

便携软件由用户在本地选择程序建立关联，再通过预检和受支持规则核对；只勾选“这是第三方软件”不能放行。未知应用保持 `RequiresReview`，提示使用软件自身迁移功能或等待维护者增加规则。支持范围宁可明确偏小，也不靠 AI 猜测安全。

已有 `quick-migrate.json` 中的自定义绝对路径必须重新过策略。个人配置只可缩小范围，不能覆盖内置拒绝或伪造已验证应用身份。

### 5.4 防绕过和执行前重验

- 字符串规范化只是第一步：处理长路径、大小写、短文件名、点段、卷别名、SUBST；通过目录句柄和最终路径/卷 ID/文件 ID 确认真实对象。
- 用路径组件边界比较，避免将 `WindowsTools` 错认为 `Windows`，也避免相似名称绕过。
- 目标尚不存在时校验每个已有祖先的身份与重解析属性；创建目标后再校验实际句柄。不允许目标经链接写进系统目录。
- 校验源/目标相同、双向祖先关系、跨任务交叉、备份包含关系、多个源映射同一目标；重叠项目阻止开始，由用户选择父或子，不静默扩大选择范围。
- 枚举拒绝访问、规则解析失败、服务清单无法读取均为无法证明安全，不返回“空/允许”。
- 加入清单、接收 AI 建议、用户开始执行、复制前、切换原路径前均重验；节点身份、内容清单、规则版本变化使计划失效。
- 关键操作尽量使用已验证句柄及受保护父目录，禁止校验后把未经验证的字符串交给任意 shell。Robocopy 仍是路径型工具，不能只靠二次 `GetFullPath` 消除 TOCTOU；对可被非可信主体改名/换链的源/目标祖先直接拒绝。安全验证必须包含并发换链测试。
- 应用关闭要求由本地检测验证；不强杀进程、不强停服务、不取得目录所有权、不放宽 ACL 来让操作继续。动态运行条件不满足则暂停等待用户。

## 6. 迁移清单和手动批量执行

### 6.1 清单契约

每项包含 `planItemId`、`scanId/nodeId`、源身份、应用 ID、完整本地源路径、目标路径、逻辑/分配大小、保守目标需求、来源（人工/AI）、建议理由、策略结论、验证时间、任务状态。

- 默认不执行、不预选 Agent 建议。用户可以删除建议项、选择允许项、设置统一目标根或逐项目标。
- 统一目标按应用和源相对路径生成，但必须展示最终路径并检测冲突，不用目录 basename 直接覆盖。
- 目标必须为空且专属于本任务；权限错误不算空。已有部分复制只能在验证事务身份后由用户选择恢复，不当作普通空目标继续。
- 计划冻结时生成 `planRevision` 和内容摘要；用户更改目录、目标或顺序即作废先前预检与确认。目标空间按队列总需求、文件系统转换和余量核对，每项开始前再次检查。
- 用户点击“开始迁移”并确认本次清单后才启动；支持取消当前任务及停止后续任务，不允许取消后仍在后台继续复制。

### 6.2 复用手动策略但修正安全接缝

新批量服务对每项使用 `MigrationService`，共享 `CopyOperationExecutor`、`MigrationWorkflowHelper` 和现有链接 API。不可直接采用一键模式的自动清理路径。

顺序如下：

1. 核对计划版本、应用停止状态、源/目标身份、特殊结构、空间与策略。
2. 持久化事务记录，预分配唯一备份路径并记录，确认不覆盖既有目录。
3. 用现有复制执行器复制到本任务目标；不得删除源文件。保留源内容不变。
4. 完成复制验证。至少核对目录/文件清单、相对路径、文件长度、ADS、必要 ACL；对新模式默认执行文件内容哈希验证。任一差异、无法读取、源期间变化均停止切换，保留原目录及本任务目标。
5. 记录“准备改名”，将原目录改名为原盘备份；写入备份实际文件 ID，再创建原路径到目标的目录链接。此时操作日志必须已能定位备份，不能等 helper 成功返回后才保存 `_backupPath`。
6. 验证链接的实际目标身份、读写能力及基本文件可达性；不只看 `ReparsePoint` 属性。
7. 记录 `AwaitingUserVerification`，保留备份并展示用户验证清单。取消原 Phase 6 自动清理，改为“记录结果与保留备份”。复制/建链 100% 不表示用户验收完成。

哈希和元数据验证是数据安全基线，不代替用户验证软件启动、资源加载、写入、重启和升级兼容性。对 ADS/ACL/稀疏等特性无法保证正确复制的目录，初始规则拒绝，而不是跳过后报成功。

`/MIR` 的保留前提是目标为本次专属并已排除并发写入；若平台验证无法证明此条件，需在共享复制器中采用不清除目标额外内容的复制模式，而非在新模式旁另写复制器。该决策需由实施阶段的并发安全验证锁定，未通过不得发布。

### 6.3 失败、取消与恢复

| 时点 | 处理 |
| --- | --- |
| 复制前/复制中失败 | 原目录保持原位；终止并等待子进程退出；保留本任务部分目标，标记失败，不自动递归清空 |
| 复制验证失败 | 不改名、不建链；展示差异，允许重新扫描和人工处理 |
| 已改名但建链失败 | 根据持久化身份记录恢复备份原名；仅删除本事务创建且目标匹配的链接，不递归删除实体目录 |
| 链接创建后健康检查失败 | 如未发生新写入且对象仍属于本事务，可恢复原状；有新数据/身份不明则保留两份并进入人工恢复，不覆盖 |
| 程序崩溃/断电 | 下次启动按事务日志核对源、目标、备份真实身份，展示待恢复任务；不得按“最新 .bak”直接决定删除或覆盖 |
| 用户验证后希望还原 | 先比较目标中的新增/修改数据，不能把旧备份直接覆盖为现状；使用现有还原流程并保留双方，另行确认多余副本处理 |
| 队列单项失败 | 保留已成功项和当前项证据，暂停后续队列；用户查看原因后可继续互不重叠的项目 |

## 7. 备份保留与人工清理

### 7.1 状态机

`RetainedUnverified → UserVerified → DeleteRequested → Deleted/Recycled`。

异常状态为 `Missing`、`IdentityChanged`、`RecoveryRequired`、`DeleteFailed/PartiallyDeleted`，均不得按成功显示。用户更改迁移目标、恢复、修复或源/目标身份异常后，原验证状态失效。

备份记录至少包含事务 ID、原路径、目标身份、备份路径与文件 ID、创建时间、复制验证摘要、用户确认时间、删除授权摘要。目录名、标记文件、扫描发现都不能单独证明归属；记录损坏或缺失时，只提供打开目录和风险提示，不提供自动认领后删除。

### 7.2 删除的两个明确确认步骤

1. 用户从“迁移记录/备份管理”主动选择备份并点击“处理原始备份”。第一个对话框展示原路径、当前目标、备份完整路径、大小和创建时间，要求勾选“已验证数据完整性”和“已验证软件兼容性”。默认取消。
2. 第二个独立确认框显示实际将删除的备份及方式；永久删除需输入目录名称或任务确认短语。多个备份逐项列出，不以一个模糊“清理全部”取代具体范围。确认绑定本次备份集合、身份和状态版本，失效后必须重新确认。

默认推荐移入回收站；支持用户主动选择永久删除以释放空间，但绝不因回收站失败/容量不足自动退化为永久删除。回收站能力和结果需用可报告逐项结果的实现核实，不能沿用现有 helper 的 `true/false` 作为“必然可恢复”的保证。

删除前核对：用户验证已完成、备份身份未变、非链接、未包含新出现的重解析点、不处于其他事务、原路径仍指向预期目标、目标可用、备份清单未变化。变化或占用则中止，不自动获得权限或删除未知新内容。

删除过程逐项记录结果，出现部分删除必须显示“部分删除，不能再视为完整回滚备份”。不承诺文件系统永久删除是原子操作。清理完成只移除对应备份记录中的活动状态，不清除审计事实。

### 7.3 全局不自动删除承诺

不以完成事件、退出程序、定时任务、磁盘空间不足、保留天数或 AI 请求触发备份删除。旧手动/一键迁移清理必须同步取消；还原、修复产生或保留的数据副本也遵循人工处置，避免旧入口破坏承诺。保留天数最多作为提醒，不能成为执行条件。

垃圾清理模式必须永久排除所有迁移备份、待恢复副本和事务目录；不会因名称包含 `.bak`、`.tmp` 或时间较久而视为垃圾。

## 8. AI / MCP 接入

### 8.1 连接方式

应用作为 MCP Server 能力提供方，用户自己的 Agent 作为 MCP Client；本软件不托管模型，不要求用户把模型 API Key 交给本软件。

建议提供独立的 `MoveFolder.McpBridge.exe`（拟定文件名），以官方 C# MCP SDK 的 **stdio** 传输运行，由 Agent 启动。Bridge 使用普通用户权限，通过受限 Windows Named Pipe 连接已打开的 WPF 应用。UI 不存在或未授权时返回 `AppUnavailable/NotAuthorized`，不能隐式拉起管理员迁移操作。

- stdout 只输出 MCP 协议，日志走 stderr。
- Bridge 仅注册显式白名单工具，不扫描整个业务程序集暴露方法。
- Named Pipe 明确设置当前登录用户/会话的 DACL、禁远程连接、首实例保护及服务端身份校验；不能使用默认 ACL。客户端校验对端进程/安装路径及握手会话，避免连接到同名伪造服务。
- WPF 高完整性进程与普通 Bridge 间需验证完整性级别和最小访问权的组合。若不同用户凭据提权导致登录主体不一致，拒绝自动配对；不得放宽为 Everyone 或要求 Agent 管理员运行。
- 初始方案不监听 TCP，不提供远程 MCP。将来若支持 Streamable HTTP，必须另行实现 loopback 绑定、认证、Origin 校验和 DNS rebinding 防护；不能把本地管道的安全假设搬到 HTTP。

### 8.2 用户授权和最小披露

用户在 UI 点“连接 AI”，确认桥接客户端和本次共享范围。配对使用短时、一次性凭据；会话凭据仅保存在受保护通道/存储，不写进日志或长期明文命令行。重启、用户撤销或关闭共享使会话失效。

默认共享应用级允许候选摘要，而非整盘全部文件：目录 ID、脱敏路径、应用、大小、风险原因、扫描时间和已批准目标候选。用户可以显式授权更多目录级视图；受保护区只提供分类及汇总，不向 Agent 枚举系统/其他用户敏感文件名。

不共享文件内容、密钥、环境变量、任意注册表、备份内容或本地审计日志。界面必须提示：用户的 Agent 可能把收到的元数据发送给其模型提供商；“本地 MCP”不等于“模型推理不出本机”。

### 8.3 MCP 工具白名单（拟定）

| 工具 | 输入 | 输出/权限 |
| --- | --- | --- |
| `get_capabilities` | 无 | 协议版本、只建议限制、当前共享能力 |
| `list_scans` | 分页游标 | 仅当前会话已授权快照摘要，不含其他扫描 |
| `get_scan_summary` | `scanId` | 容量、覆盖状态、候选汇总、扫描年龄 |
| `list_directory_children` | `scanId,nodeId,cursor,pageSize` | 仅授权目录级节点，服务端限制页大小；不可借路径跳出范围 |
| `list_migration_candidates` | `scanId,cursor,pageSize` | 通过本地规则筛选的候选，含风险和空间口径 |
| `get_candidate_details` | `scanId,nodeId` | 应用归属证据、允许条件和当前阻断原因 |
| `get_migration_policy` | 无 | 可公开的拒绝类别与稳定原因码，不能修改 |
| `submit_migration_proposal` | `scanId,policyVersion,clientRequestId,items[]` | 仅提交建议文档到收件箱，逐项返回接受/拒绝；不是执行计划 |
| `get_proposal_status` | `proposalId` | 收到/已审阅/已拒绝/已失效，不授权执行 |

没有 `migrate`、`delete`、`cleanup`、`restore`、`run_command`、任意 `read_file`、`set_policy`、`approve` 或批量执行工具。也不通过 resources、prompts、URI handler、CLI 开关或 IPC 隐藏提供这些能力。Agent 不能启动新扫描或扩大共享范围，只能读取用户已经生成并授权的结果。

只读工具可标记 `readOnlyHint=true`；提交建议会修改应用的建议收件箱，应标记 `readOnlyHint=false, destructiveHint=false`。这些 annotations 只是提示，真正权限边界是注册集合、服务端验证与执行器隔离。

### 8.4 建议数据契约示例

以下是结构示例，不对应真实目录或当前实现：

```json
{
  "schemaVersion": 1,
  "clientRequestId": "example-request-001",
  "scanId": "example-scan-001",
  "policyVersion": "example-policy-001",
  "items": [
    {
      "nodeId": "example-node-042",
      "targetCandidateId": "example-target-002",
      "priority": 1,
      "reason": "该目录为已识别软件的独立模型资源，建议由用户审核后迁移",
      "compatibilityNotes": "仍需用户验证资源加载和升级兼容性"
    }
  ]
}
```

Agent 只能提交服务端发放的节点 ID 和用户预先批准的目标候选 ID；没有目标授权时可以省略目标，由用户在 UI 设置。不接受绝对路径、通配符、命令、`approved=true` 或自报空间数字作为执行依据。示例 ID 不是权限令牌。

服务端执行字段白名单、版本、长度/条目数/分页大小限制，检查授权范围、节点存在性、系统拒绝规则、重复项和父子重叠。建议文字按纯文本显示，禁止执行链接、脚本或命令。相同 `clientRequestId` 与相同正文返回原回执，不重复导入；不同正文使用相同 ID 则拒绝。

建议接收后状态为 `Received`，用户审阅后可以“加入待迁移清单”。**这不是批准执行。** 仍需用户在应用内设置目标、完成预检、点击开始并确认。审阅、导入和执行是三个不同动作。

### 8.5 威胁模型与限制

- 文件名、应用名称、Agent 理由都可能包含提示注入；按不可信数据处理，不让其改变策略或权限。
- 会话校验范围、节点 ID 归属、分页游标绑定快照；跨会话/越权 ID 返回拒绝，不泄漏路径。
- 快照更新、撤销授权、策略升级、对象消失或身份改变使旧建议失效；用户重新审阅，不自动迁移到“同名新目录”。
- 访问和建议回执记录最小本地审计，不记录机密、全盘路径列表或文件内容。
- 本软件能够保证自身 MCP/IPC 不提供执行权，**不能约束 Agent 已经拥有的其他工具**。若用户另行给予 Agent 任意 shell、文件系统、管理员或 UI 自动化权限，Agent 可绕过应用直接操作系统；应在接入说明中建议使用受限 Agent 配置。这不是靠提示词能解决的问题。

## 9. 独立垃圾清理模式

### 9.1 产品边界

清理是独立模式、独立选择、独立确认，不随迁移成功运行，也不交给 AI 执行。初始支持经过逐规则审查的第三方软件**可重建缓存和过期诊断日志**，不把所有临时目录一概视为安全。

默认不包括：Windows/更新/Installer/WinSxS、注册表、驱动、浏览器登录凭据/会话/书签/历史、用户文档、下载目录、游戏存档、模型资源、软件数据库、云同步占位文件、整棵 AppData、回收站清空、重复文件和迁移备份。

未知应用/版本不执行清理；没有安全匹配时显示“未发现受支持的清理项目”，不为了显示收益增加泛化规则。

### 9.2 规则模型

声明式 `CleanupRule` 包含：`ruleId/version`、应用识别条件、适用版本、受限已知根目录、相对匹配模式、排除项、最小年龄、要求退出的进程、风险说明、数据是否可重建、预览说明、允许动作、来源和审核记录。

- 支持精确相对目录和根内有界匹配；禁止绝对任意路径、上级跳转、跨根 glob、可执行脚本、任意命令、注册表删除、truncate/shred。
- 不接受用户从网络直接导入后执行的 CleanerML/Winapp2 文件；外部规则仅作人工研究依据。
- 规则随应用发布，版本固定；如未来支持独立更新，需签名、审查和版本回退机制，不以在线规则静默扩大删除范围。
- 根目录从可信 Known Folder/应用定位器解析，不把 Agent、用户环境变量或规则文本中的路径原样当授权。
- 迁移与清理共用底层路径身份/保护区检查，但允许条件不同：一个目录允许迁移不代表允许删除；缓存可清理也不意味着可以迁移其整个应用。

### 9.3 用户流程与数据安全

1. 用户选择清理类别后点击“扫描垃圾”；只读枚举匹配文件，展示应用、规则、实际路径、数量、大小、原因、可恢复性和占用状态。
2. 默认不勾选，用户逐项选择；形成固定 `CleanupPreview`，绑定规则版本和文件 ID、长度、时间等身份信息。
3. 用户点击“清理所选”，确认范围及影响；执行前重新枚举并比较预览。新增、变更、正在使用或无法验证的文件不进入执行，要求刷新预览。
4. 默认动作是移入本应用受保护的**同卷隔离区**，保留原相对路径与身份映射。不同卷不做“复制后删源”的隐式替代。隔离失败就保留原文件。
5. 清理结果明确区分“已隔离”“跳过/失败”“尚未释放空间”；隔离不等于物理空间已释放。用户可在隔离区恢复，原路径已有新文件时不覆盖，展示冲突。
6. 用户需要实际释放空间时，在隔离管理中主动永久删除，并再次确认具体集合。也可显式选择回收站，但回收站不能保证立刻释放空间；不自动清空、不按到期时间自动删除。

同卷原子改名只能降低部分失败风险，不能保证批量隔离原子性。每个文件记录结果；取消后只停止后续项，不伪报全成功。清理与迁移/备份管理使用同一排他执行闸门。应用仍运行时阻止对应清理，不强杀、不截断日志、不强制删除占用文件。

### 9.4 开源借鉴结论

| 项目 | 核实到的价值 | 采用与不采用 |
| --- | --- | --- |
| BleachBit / CleanerML | 规则分应用和选项；先 Preview 后 Delete；可声明运行进程，XML/XSD；同时支持注册表、进程和破坏性动作 | 借鉴“检测、范围、预览、运行阻断”结构；不导入全量规则，不复制清理执行器 |
| Winapp2 | 明确应用与路径关联的声明式规则；默认未选中；文档承认误用及不可逆风险 | 作为规则研究目录，不把数量或社区贡献视为安全保证；不启用 Winapp3 激进规则 |

安全规则需要用真实受支持应用版本验证“缓存可再生且不包含用户数据”，开源名称或文件后缀不是验证证据。

## 12. 验收和验证方案

所有写入、迁移、回滚、故障和删除测试使用可丢弃目录/虚拟磁盘/VM；不得使用用户真实目录，禁止为测试改动真实 Windows 目录。系统路径测试使用解析器夹具；真实系统只做读取核对。

| 验收域 | 必测场景 | 通过标准 |
| --- | --- | --- |
| MFT | 百万级项、碎片 MFT、扩展属性、短名、硬链接、ADS、resident、稀疏/压缩、坏记录、文件 ID 复用 | 不越界；树关系正确；大小口径可解释；未知显式标记 |
| 扫描能力 | 普通用户后端、NTFS/非 NTFS、权限拒绝、锁定卷、取消 | 不伪称 MFT/完整；不写卷、不修改 USN；UI 可响应 |
| 路径保护 | 非 C 盘 Windows、大小写/短名/SUBST/卷 GUID、源和目标 junction、相似前缀 | 同一物理禁区一致拒绝；合法相似前缀不误判 |
| 应用规则 | 未知 exe、伪造卸载项、第三方驱动/服务、安全软件、受支持普通资源目录 | 只有可靠应用规则和实时检查通过才允许 |
| 批量计划 | 父子重叠、目标碰撞、源目标互含、空间不足、目标拒绝访问 | 不开始、不覆盖、不把异常当空 |
| 复制和切换 | 锁定文件、退出码错误、同长度不同内容、ADS/ACL 差异、复制期间源变更 | 验证失败不改名建链，源保持可用；无静默成功 |
| 并发攻击 | 检查后目标被换成链接、父目录改名、目标新增用户文件 | 不能写入受保护区或删除非本任务数据；无法证明则不发布该路径能力 |
| 恢复 | 在复制/改名/建链/落盘各点故障注入和断电 | 找得到全部副本；不靠名字猜；不覆盖新增数据 |
| 保留备份 | 各模式成功、失败、重启、退出、空间不足 | 不自动删除原始备份/数据副本；结果显示待验证 |
| 手动删除 | 未验证、仅第一次确认、确认后目录变化、回收站失败、部分删除 | 无授权不删；无永久删除回退；准确显示结果 |
| MCP | tools/list、猜测删除工具、越权 nodeId、伪造路径、改策略、提示注入、重放、撤销、失效建议 | 只能读授权元数据/提交建议；文件系统无变更；不形成提权代理 |
| 清理 | 浏览器登录数据与缓存并存、规则过期、新文件出现、运行中、链接、备份伪装 tmp | 只处理预览内已核实的允许对象；所有保护对象不动 |
| 空间收益 | 备份保留、同卷隔离、回收站、永久删除 | 前三者不虚报释放；最终以卷空闲变化为观测而非承诺 |
| UI | 1000×700、宽屏、高 DPI、键盘、长路径、树展开、确认取消 | 无关键按钮遮挡；危险动作无默认同意；禁用原因可见 |
| 旧模式 | 手动、一键、还原、修复、已有配置和迁移记录 | 保留正常流程；新增安全拒绝明确提示，不绕过保留/确认政策 |

验证层次：解析器/策略确定性测试 → 可丢弃 NTFS 卷的真实扫描与迁移烟测 → 真实 WPF 页面操作 → 受限 Agent 客户端 MCP 会话 → 打包后运行。仅编译或 mock 工具调用不能证明完成。

发布硬门槛：自动删除路径已清除；系统/高危源目标不能通过任意入口绕过；MFT 主路径确实跑通；取消后无残留复制；断电能定位原件；备份双确认可验证；Agent 无执行接口；清理不触碰保护数据。任何一项未通过不得以“基础版”名义发布写操作。

## 13. 风险、决策与待实测项

### 13.1 已作出的设计选择

- MFT 原始读取为主路径，USN 枚举不能独立承担大小统计。
- 迁移执行继续用现有手动服务，清单仅组织任务。
- 禁迁策略在核心层强制执行，第三方兼容规则之外默认不允许。
- 原始备份必须保留，用户验证和二次确认后才可删除；对旧入口同步收紧。
- MCP 采用普通权限 stdio Bridge，不开放网络端口，不暴露执行能力。
- 清理采用受审查声明式规则，先预览、默认可恢复隔离，不自动释放隔离数据。
- 未对接云端 AI，不导入 GPL 清理执行器或整套社区规则，不更换项目许可证。

### 13.2 实施前需锁定的验证结果

这些是技术发布门槛，不是留给用户补充的需求，也不阻止本设计文档完成。

| 风险/未知 | 推荐处理与失败后行为 |
| --- | --- |
| 原始 NTFS 解析完整性与性能尚未在本项目验证 | 用合成/碎片化测试卷及对照遍历验证；不完整区只读，不能以降级遍历宣称完成 MFT 能力 |
| 具体软件/版本对符号链接的兼容性 | 建立逐应用规则与真实验证记录；未验证应用保持只读/待核对 |
| `/MIR` 的并发安全边界 | 以专属目标/身份锁定测试证明；不满足则在共享执行器改非删除复制策略 |
| 高完整性 WPF 与普通权限 Bridge 的 Named Pipe 访问 | 测试同 SID 不同完整性级别、不同登录会话和替代凭据提权；不以放宽 ACL 解决 |
| 永久删除/回收站的部分失败与可恢复性 | 逐项结果、禁止自动回退；取消或失败时显示真实剩余状态 |
| 外部项目许可证及维护质量 | 固定版本/commit 后审查；未审查前仅作为设计参考，不成为产品依赖 |
| 操作系统外部权限不可控制 | 明示本软件只限制自身接口；用户需限制 Agent 其他高权限工具 |
