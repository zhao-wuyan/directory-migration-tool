# 单文件自更新与 Lite 版运行时补装规划（暂缓实施）

> 状态：**规划已记录，暂不实施**  
> 适用范围：绿色免安装单文件形态（Lite 框架依赖版为主，自更新链路同时兼容自包含完整版）  
> 实测约束：当前网络实测微软 `aka.ms` 直链下载速度仅约 **100 KB/s**，后期计划更换为更快的自定义下载地址；因此在回退下载 `aka.ms`（及任意直链兜底）时，**提示框必须提供可复制的完整下载地址**，且下载源必须集中配置、便于后期替换。

---

## 1. 目标与设计边界

1. **保持绿色单文件体验**：不强制引入重型安装向导，单文件直接可运行、可自更新。
2. **采用“方式 2：新版自举接力替换”实现自更新**：不依赖外部 `.bat`/`.ps1` 替换脚本，也不在运行中重命名当前 `.exe`，降低杀毒软件误报风险。
3. **Lite 版运行时自动检测与补装**：在首次启动（外部引导层）以及未来跨 `.NET` 大版本自更新前，自动检测本机是否具备对应大版本的 `.NET Desktop Runtime (x64)`，缺失时支持自动补装或复制链接手动下载。
4. **分发文件名收敛**：当前 [publish.ps1](../publish.ps1) 会将产物重命名为带版本号的 `目录迁移工具-v1.1.7-lite.exe`；落地自更新时，正式运行的单文件名应固定为 `目录迁移工具.exe`（版本号体现在压缩包名、程序属性与应用内 UI），避免更新后桌面快捷方式失效。

## 2. 单文件自更新方案（方式 2：新版自举接力替换）

### 2.1 更新清单设计（`latest.json`）

通过远端托管的 `latest.json` 下发版本信息与下载地址，便于后续随时切换高速源而无需重新发版客户端：

```json
{
  "version": "1.2.0",
  "releaseNotes": "1. ...\n2. ...",
  "requiredDotNetMajor": 8,
  "packages": {
    "lite": {
      "urls": [
        "https://your-fast-mirror.example.com/directory-migration-tool/v1.2.0/目录迁移工具-lite.exe"
      ],
      "sha256": "<64位十六进制摘要>",
      "sizeBytes": 5242880
    },
    "selfContained": {
      "urls": [
        "https://your-fast-mirror.example.com/directory-migration-tool/v1.2.0/目录迁移工具.exe"
      ],
      "sha256": "<64位十六进制摘要>",
      "sizeBytes": 75497472
    }
  },
  "runtimeDownloads": {
    "8": {
      "primaryUrls": [],
      "fallbackUrl": "https://aka.ms/dotnet/8.0/windowsdesktop-runtime-win-x64.exe",
      "sha256": ""
    },
    "10": {
      "primaryUrls": [],
      "fallbackUrl": "https://aka.ms/dotnet/10.0/windowsdesktop-runtime-win-x64.exe",
      "sha256": ""
    }
  }
}
```

### 2.2 自更新执行流程

1. **版本检查与确认**
   - 启动后按需（或用户手动点击“检查更新”）拉取 `latest.json`，比对当前版本。
   - 发现新版本后弹窗展示版本号与更新日志，由用户确认是否开始更新；若当前有正在执行的迁移、还原或扫描任务，禁止立即重启更新。
2. **下载到临时目录并校验完整性**
   - 按当前运行形态（Lite / 自包含）依次尝试 `packages.<mode>.urls` 下载到：
     `%TEMP%\MoveWithSymlink\updates\<version>\目录迁移工具.exe`
   - 下载完成后**强制校验 SHA-256**；校验失败或下载中断时删除临时文件、提示失败原因并保持旧版不动。
3. **跨 .NET 大版本前置检查（仅 Lite 版）**
   - 若 `requiredDotNetMajor` 大于当前已安装的 `.NET Desktop Runtime` 大版本（例如未来从 `.NET 8` 升级到 `.NET 10`），**在接力替换前**先执行第 3 节的运行时检测与补装，确认目标运行时已就绪后再继续，避免替换完新版无法启动。
4. **新版自举接力替换**
   - 旧进程拉起临时目录里的新版 exe，并传入接力参数：
     ```text
     <TempNewExe> --apply-update --parent-pid <旧进程PID> --target-path "<原exe完整路径>"
     ```
   - 确认临时进程成功启动后，旧进程立即正常退出。
5. **等待退出、安全覆盖与重启**
   - 临时新版在 `App.OnStartup` 最早期识别 `--apply-update`，不加载主窗口（或仅显示极简更新进度提示）。
   - 等待 `--parent-pid` 进程完全退出（带超时与文件可写重试，例如最多 15 秒）。
   - 将原 exe 备份为 `<原exe>.bak`，再把临时新版复制到 `--target-path` 并复核目标文件 SHA-256。
   - 覆盖成功后，启动正式路径的新版并附带清理参数：
     ```text
     "<原exe完整路径>" --cleanup-update "<TempNewExe>"
     ```
   - 若覆盖过程出错，自动将 `<原exe>.bak` 恢复为原文件名并弹出错误提示，确保旧版可继续使用。
6. **清理残余**
   - 正式路径的新版启动后，异步删除 `<TempNewExe>` 所在临时更新目录及同目录 `<原exe>.bak`。

### 2.3 安全与兼容性约束

- **参数校验**：`--apply-update` 必须校验 `--target-path` 为现有 `.exe` 路径，防止参数被滥用覆盖无关文件。
- **权限继承**：本工具本身以管理员权限运行，接力进程天然继承管理员权限，即使单文件位于 `C:\Program Files\` 等受保护目录也可正常替换。
- **单文件自解压隔离**：保持 `IncludeAllContentForSelfExtract=true`；新版 exe 内容哈希变化后，.NET 会自动解压 `handle.exe`、`version.json` 到独立的 `%TEMP%\.net\` 子目录，不与旧版临时解压目录冲突。

## 3. Lite 版 .NET 运行时检测与补装方案

> 说明：Lite 版 exe 自身依赖 `.NET Desktop Runtime`，若目标机器未安装对应版本，系统宿主会在进入 C# `Main()` 前拦截。因此需要“外部引导层（首次运行）+ 应用内前置检测（跨大版本更新）”两处协同。

### 3.1 运行时检测逻辑（不依赖 `dotnet` 命令）

按以下顺序判断是否已安装目标大版本（`<Major>` = `8` 或 `10`）的 x64 Desktop Runtime：
1. 检查目录 `%ProgramFiles%\dotnet\shared\Microsoft.WindowsDesktop.App\<Major>.*` 是否存在且非空；
2. 辅助检查注册表 `HKLM\SOFTWARE\dotnet\Setup\InstalledVersions\x64\sharedfx\Microsoft.WindowsDesktop.App`；
3. 必要时辅助核对 `dotnet --list-runtimes` 输出中的 `Microsoft.WindowsDesktop.App <Major>.`。

### 3.2 下载源优先级与可替换设计

禁止在代码中分散写死 `aka.ms` 地址，所有运行时下载地址统一收口到单一配置（优先采用 `latest.json` 的 `runtimeDownloads`，离线/未拉取清单时使用内置默认配置）：

1. **优先级 1：自定义高速镜像源（后期替换目标）**
   - 配置于 `runtimeDownloads.<Major>.primaryUrls`；下载后验证微软 Authenticode 数字签名（及可选 SHA-256）。
2. **优先级 2：`winget` 自动安装（可选前序尝试）**
   - 若本机存在 `winget`，可尝试执行：
     ```powershell
     winget install Microsoft.DotNet.DesktopRuntime.<Major> --accept-package-agreements --accept-source-agreements
     ```
3. **优先级 3：回退微软官方直链（`aka.ms`）**
   - `.NET 8`：`https://aka.ms/dotnet/8.0/windowsdesktop-runtime-win-x64.exe`
   - `.NET 10`：`https://aka.ms/dotnet/10.0/windowsdesktop-runtime-win-x64.exe`

下载安装包并校验通过后，以半静默模式执行安装（显示微软官方进度条、无需人工点“下一步”）：
```powershell
windowsdesktop-runtime-win-x64.exe /install /passive /norestart
```

### 3.3 回退下载 `aka.ms` 的交互硬性要求

鉴于实测 `aka.ms` 下载速度仅约 **100 KB/s**，约 55 MB 的运行时安装包在程序内单线程拉取耗时较长且易中断，**任何回退到 `aka.ms`（或自定义直链下载）的提示框必须满足以下交互设计**：

1. **地址必须可复制**：
   - 使用只读可选中文本框（`TextBox` + `IsReadOnly="True"`）完整展示当前下载地址，禁止使用无法选中复制的普通 `TextBlock` / `MessageBox` 纯文本。
   - 紧邻文本框提供 **“复制下载地址”** 按钮，点击后一键写入剪贴板并给出明确反馈（如按钮切换为“已复制”）。
2. **提供多种获取方式**：
   - **直接在此下载并安装**（带实时速度、已下载大小、进度条与“取消”按钮；低速时提示用户可改用外部下载器）；
   - **在浏览器打开**；
   - **复制下载地址**（供用户粘贴到 IDM / 迅雷 / 浏览器自行加速下载）；
   - **我已手动安装，重新检测**（用户手动装完后点击即可无缝继续启动或更新，不必重头再来）。
3. **脚本/控制台引导（如 `run.ps1`）同步对齐**：
   - 终端中完整输出可复制直链，并提供按键直接调用 `Set-Clipboard` 复制到剪贴板，避免用户手动框选截断 URL。

## 4. 后续实施时的代码触点清单

正式开工时预计涉及以下文件与模块：

- **`publish.ps1`**：
  - 区分内部运行固定文件名（`目录迁移工具.exe`）与对外带版本号的发布包/归档命名；
  - 打包结束时自动输出 SHA-256 摘要，并可生成/更新 `latest.json` 清单片段。
- **`MigrationCore/Services/Update/`（新增）**：
  - `UpdateManifest.cs`：`latest.json` 数据模型（含主备下载地址、`requiredDotNetMajor`、`runtimeDownloads`）；
  - `RuntimeCheckService.cs`：`.NET Desktop Runtime` 本地检测、下载源解析与签名/哈希校验；
  - `AppUpdateService.cs`：版本比对、分块下载与进度/实时速率上报、SHA-256 校验、触发新版自举接力。
- **`MoveWithSymlinkWPF/App.xaml.cs`**：
  - 在 `OnStartup` 最前端处理 `--apply-update`（等待旧 PID 退出、备份覆盖、复核并重启正式版）与 `--cleanup-update`（清理临时目录与 `.bak`）。
- **`MoveWithSymlinkWPF/Views/`（新增弹窗）**：
  - 更新确认与下载进度窗口；
  - 运行时缺失与回退下载提示窗口（强制包含**只读可复制 URL 文本框 + 一键复制按钮 + 重新检测按钮**）。
- **`run.ps1`**：
  - 扩展 Lite 版运行时缺失处理：支持优先自定义源 / `winget` / 回退 `aka.ms`，并在回退时打印且支持一键复制下载地址。

## 5. 验收与回归测试基线

未来落地实现后，合并前需完成以下验证：

1. **自更新主链路**：同大版本 `Lite → Lite`、`自包含 → 自包含` 接力替换成功，原路径 exe 替换为新版，临时文件与 `.bak` 自动清理干净。
2. **异常与回滚**：
   - 下载文件 SHA-256 不匹配时拒绝替换，旧版完好；
   - 模拟原 exe 长时间占用导致覆盖超时时，保留/恢复旧版并给出明确提示；
   - 活动迁移任务进行中阻止立即重启更新。
3. **运行时补装与回退体验**：
   - 在无目标 Desktop Runtime 的测试环境触发补装，验证自定义主源优先命中；
   - 模拟主源不可用回退到 `aka.ms`：验证提示框内下载地址**可直接选中复制**、**“复制下载地址”按钮可用**、取消低速下载后手动安装并点击“重新检测”能顺利继续。
4. **跨大版本模拟**：配置 `requiredDotNetMajor` 高于本机版本，确认 Lite 版先完成运行时检测与补装，再执行 exe 接力替换。
